## 本轮：场景直接写 60×20

- 持久 char_buf 保存 60×20 字符、属性及光标标记；核心负责覆盖、清除、换行和分区滚动。
- 同一张静态 4096 B framebuffer 从 char_buf 光栅化；framebuffer 不管理终端行为。
- SDL 默认使用直接布局核心，不再运行“80×24 字符画布 → Layout60”转换，也不建立动态 Section。
- 原始终端核心继续供 Python 对照测试使用；不把参考模型的画布带入新的运行实例。
- 海洋、随机状态、文本和历史属于动画状态，不假称整个程序只需两块显示缓冲。
- 保持事件、时间、随机抽取和业务状态；对比旧 60×20 输出并报告直接覆盖/换行导致的差异。
  静态面板、标题文案、字形、光标和图形边界须有自动检查；完整观感仍由用户目视验收。
- 每个可构建、验证的节点本地提交。没有完成的项目不勾选。

## 后续候选（本轮不混入）

1. 删除剩余短命解码/复制；为 scratch、历史定义初始化容量和生命周期，目标是正常播放零分配。
2. 高频海洋随机概率用同样 53 位随机整数和等价阈值，减少 double；保持 RNG 抽取顺序与边界。
3. 节拍改整数时间与余数累积；场景离散 pow 参数查表，低频天气定点化另做误差/语义评估。
4. 替换固定 CLEAR 格式的 sscanf；评估浮点 snprintf 的目标链接成本、错误回调和 gc-sections/LTO。
5. 海洋字符窄化、文本 Flash 引用与可变覆盖；不直接把有随机修改/原地拆行的副本视为只读。
6. 用目标 cycle/stack/map 数据决定光栅化缓存、局部传输及 XIP 缓存优化；不将宿主时间外推 MCU。

直接布局优先于给旧 Section 分配器加池。若某种终端特殊语义确需暂存，先证明必要性并明确容量，
不能悄悄恢复完整 80×24 中间画布。
