# 优化状态与板端测量候选

库已交付。本文不是自动续开发计划；新项目先接入并测量，只有用户要求且有数据依据时才优化。接口见 [ANIMATOR_API.md](ANIMATOR_API.md)，历史测量入口见 [HANDOFF.md](HANDOFF.md)。

## 已完成

- 直接60×20 char_buf，单4096 B framebuffer；无80×24中间画布或动态Section。
- 原生60×8海洋、独立状态与整数概率，分离持久损坏/临时闪烁。
- 原生pow/cos离散查表，Q32.32播放器使用有理余数进位；不采用低精度整秒时间。
- Animator自有固定工作区；scratch/历史初始化预留，核心无显式堆调用、播放零预留。ARM对象34752 B已包含这些容量。
- 单头库、公共时钟/帧接口，SDL通过同一接口使用核心。
- 天气改float和84 B小表正弦，原生移除double/sin/浮点printf；误差与随机画面差异见NATIVE_FLOAT.md。

## 板端数据出来后再考虑

- 单精度天气、整数snprintf、固定格式sscanf、错误处理对目标周期与ROM的影响。优先查表，查表不可行时再评估定点误差，不先改算法。
- 单函数/完整调用链栈峰值，长停顿补算峰值；显示总线/DMA占用是否比渲染更慢。
- 文本只读引用或更紧凑的历史存储；先区分随机修改/拆行副本与真正可放Flash的数据。
- 按目标map评估gc-sections/LTO及运行库；按周期数据评估像素生成、局部传输或XIP相关优化。

MCU_PROFILE.md、HOTSPOTS.md中的旧堆与浮点统计是对应提交的优化前证据；不能代替当前profile。每项变化都需输出/状态回归并明确资源收益，不能把Windows耗时直接外推Cortex-M0。
