# 原生核心热点复核 — 2026-10-06

基线48d2204。本轮只修改profiling工具和文档，未修改生产算法。Windows CRT、SDL、PCM、EXE内嵌WAV不计入MCU核心预算。

## 方法和边界

profile_core.py新增调用点总数/单帧峰值，三个种子各6509帧。插桩与原始构建的每帧字符、framebuffer、主RNG摘要一致；调用点之和与库函数总数自检通过。

profile_math.py在原始源码-O3编译后，通过链接器wrap统计pow/sin/cos/floor实际外部调用，输出摘要同样一致。它不统计数学库内部运算；插桩耗时不当作原始性能。优化后LLVM IR用于验证重复调用及浮点运算。源码执行次数不等于机器CALL数量。

```powershell
python tools/profile_core.py --cc .tools/llvm-mingw-20260922-ucrt-x86_64/bin/clang.exe --native --out build/profile-hotspots
python tools/profile_math.py --cc .tools/llvm-mingw-20260922-ucrt-x86_64/bin/clang.exe --out build/profile-hotspots
```

## 浮点位置与频率

下表为seed1；三个种子的外部数学调用总数相同。

| 位置 | 全程次数 | 单帧峰值 | 判断 |
|---|---:|---:|---|
| access_grid的pow | 源792；实际720（总量减其余调用点） | 72，帧4460 | 同一输入在循环重复计算，编译器未完全移出 |
| 海洋C文字选择pow | 2072 | 4 | 三个发生器使用同一beat和指数1.2，可共享结果 |
| 开场/擦除噪声pow | 91 | 1 | 次数少，仍依赖double pow |
| 掉电pow | 0 | 0 | 默认时间线不执行，不代表代码已删除 |
| 海面surface | 954 | 61，帧60 | 每列3 sin、1 cos；入场突发值得注意 |
| 天气sin | 1002 | 14，帧2620 | 模拟循环还伴随大量double加乘除、转换和比较 |
| 天气逐字符浮点比较 | 11516 | 72 | randint转double再比较，可在字符串外转换等价整数阈值 |
| 天气浮点snprintf | 177 | 1 | 频率不高，但可能影响目标Flash |

全曲实际外部调用：pow2883、sin3864、cos954、floor942。入场一帧有183次sin和61次cos。源码pow2955、floor955次；差异来自编译优化。fabs源码4008次，但原生对象不导入fabs，编译为内联绝对值。

大部分数值是double，单精度FPU不能直接加速全部计算。将原始surface函数体独立编译为Cortex-M4 soft ABI，确实生成 `__aeabi_i2d`、`__aeabi_ddiv`（两处）、`__aeabi_dmul`、`__aeabi_dadd`、`__aeabi_d2iz`，以及sin/cos/floor调用。此探针只声明数学接口，没有目标libc链接、MCU运行或周期测量。是否赶得上约41.9ms节拍仍需板端验证。

## 高频播放器路径

player_sync/player_step每次轮询都做double时间加减、节拍乘法与比较。player_delay的60/179/8已折叠成常数，不能说每轮进行除法。

确定性模拟1000Hz为275618次轮询，100Hz为27562次，都产生6509动画帧且最终字符摘要相同。各5次主机循环耗时中位数13.4534ms/10.6690ms，均含动画、不含光栅化，受主机调度影响，不是板端周期或纯player耗时，也不替代暂停/输入边界回归。

MCU优先考虑音频采样计数/整数时间、截止时间及余数累积，保留暂停、快进和严格边界。SDL约1ms轮询是主机策略，不必固化成MCU接口。

## 非浮点热点及代码体积

- 海洋乱码已整数化：seed1共734411次概率检查、748575次xorshift。概率比较含64位乘法，可考虑绘制前算32位阈值；必须保留<=边界和饱和时RNG抽取，不以降低乱闪频率换性能。
- 光栅化无浮点。6509帧扫描7810800字符，源码glyph_bits通常内联。非插桩主机像素阶段139.26–147.95ms，动画11.92–12.49ms，像素生成是主机更大的CPU项。可测空白跳过、字形行掩码、变化格更新，不自动增添第二张framebuffer。
- 原生text.c对象仍引用sscanf，虽然默认时间线执行0次；按词CLEAR分支保留了扫描器。可用有界整数解析替代。
- snprintf共2065次，其中浮点177次；错误处理仍引用fprintf/abort。目标libc、链接粒度、gc-sections/LTO决定实际Flash代价，Windows对象/EXE不能给出MCU字节数。可提供目标错误回调，但不能静默忽略容量错误。
- 只减少pow次数不会删除pow库的Flash占用；需要全部替换其用途才能消除依赖。性能与代码体积须分别测量。

## 分配与XIP内存

没有画布/海洋每帧分配。完整播放39次分配：初始化28、scratch4、历史7，销毁live=0。

主机堆峰值25184B：文本字符11350、行描述5680、scratch858、历史7296。ARM ABI/轨迹投影堆20116B，加Credits10264B、fb4096B，总主要对象34476B（33.67KiB），不含栈、分配器、驱动和少量可写静态对象。

RAM后续重点为将不变文本/行表留在Flash，拆出随机改写、原地拆行所需部分；不再处理已经消除的画布malloc。历史/scratch可按测量预留，但默认时间线峰值不是全部未来输入的容量证明。

## 已验证的局部实验和优先顺序

仅在build内将access_grid的limit移到循环外，且只在randomize时计算。实际pow **2883→2173，减少710次（24.6%）**；全曲pow单帧峰值72→4。三个种子的每帧字符/像素/主RNG摘要均不变。正式源码尚未应用，不宣称发布版已提速；插桩时间不用于承诺性能比例。

1. 先应用访问点不变量移动；随后验证海洋C共享pow、天气逐字整数比较，保留随机抽取。
2. 目标播放器采用整数时间，按交互回放验收。
3. 海面查表/定点重点测61列入场突发；天气定点化单独验证舍入及分类变化。
4. 用目标map裁剪扫描器、浮点格式化和错误运行库，测真实Flash/XIP占用。
5. 按板端CPU/总线测量处理像素生成、传输和海洋整数阈值。

本轮没有改动画行为或重新构建发布EXE，也未重复无关CTest。证据在docs/validation/2026-10-06/hotspots；完整IR/实验EXE位于build/profile-hotspots。
