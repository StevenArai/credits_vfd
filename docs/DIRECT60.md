# 场景直接写 60×20 字符画布

本轮分支 codex/direct-60x20，参考基线 f043f98。优化方向先记录于 OPTIMIZATION_PLAN.md。

## 运行结构

SDL 链接 credits_core60；它不包含 canvas.c 的 Section 管理或 layout60.c 的后处理。
SDL 前端只把核心提供的字符画布交给核心光栅化函数，显示 framebuffer，并适配时间/输入/音频。
所有场景坐标、换行、滚动、覆盖、光标和字体仍在无 SDL 依赖的 C 模块中。

```
场景 / 文字 / 海洋状态
        ↓ 直接写入
Canvas.cells[1200]   60×20，uint32_t 字符 + 属性 + 光标标志
        ↓ framebuffer_render60
Framebuffer.bits[4096]   256×128，1bpp
        ↓
SDL 或将来的硬件显示适配
```

SDL 的 Credits 实例与 framebuffer 均为静态存储。字符画布为实例内的唯一字符格数组，
4800 B；另有 12 B 的背景/滚动/裁剪计数。没有第二张 Layout60，也没有 80×24 中间画布。
海洋已按用户授权改为原生 60×8 单字节状态，每次左移一列，只生成右侧新列；不做横纵重采样。
每份海洋独立持有相位和随机状态。具体变化及最新内存见下方“原生海洋运动”。

credits_core 是独立的终端参考构建，继续运行 Python 对照。共享随机、调度、事件、
初始化、天气计算与文字业务状态；scenes.c / scenes60.c 分别提供参考和直接布局。
二者只在各自的静态库中编译，不在 SDL 运行实例里并存。当前两份场景回调仍有相似逻辑，
因此新增逐拍业务摘要对照，防止直接布局改变随机抽取及事件行为。

## 原生分区与有意变化

| 内容 | 直接布局 |
|---|---|
| 海洋 | 行 12–19，60×8；上方文字按词换行并在自己的区域滚动 |
| 标题与节拍块 | 用户文案直接写入；块位于 (26,7)，8×4 |
| 天气 | (32,11)，28×7；日期、天气、风速等直接写入该面板 |
| 资助历史 | 左侧 31×18，完整新行向上滚动；当前输入位于行 19 |
| 加载条 | (13,7)，34×3；进度限定在 32 格内部，文字在行 11 以下 |
| 双路文字 | 顶部文字区、行 12–18 历史区、行 19 输入，各自管理换行 |
| 接入点 | 原 24 个节点按 60 列直接放置，底部状态三行 |
| 结尾 | 文字在行 1–5，节拍块在行 7–10，底部文字在行 16–19 |

普通覆盖使用调用顺序；不再模拟 Python Section 排序和跨 80 列写入的副作用。
开场噪声坐标映射到本地 60×20，保留随机调用；原加载条越界到框外的内容不再显示。
文字在目标区域按词换行/滚动，清除自身区域；资助历史去除前后填充空格后加前缀。
结尾文字避开节拍块。标题、面板的空白格可能保留不同属性，但无可见像素差异。
这些变化属于直接布局，不能声称整曲逐像素不变；最终内容/观感由用户检查。

## 海面轮廓修正（历史方案，已由原生海洋替代）

用户已目视接受直接布局，另指出海面 # 缺口。旧10→8点采样跳过源行4/8，
即使与旧布局逐格一致，也会丢失一格厚的海面。现在将行4/5和8/9分别合并，
保留组内实际渲染的 #；没有 # 时沿用末行字符，随机故障仍由原算法生成。
新 ocean60_contour 独立对照测试覆盖全部高度与故障档位，不再用有同样缺陷的
旧布局作为轮廓正确性的依据。整体布局已接受，此修复待用户复看。
不增加画布、堆或分配次数；验证和资源数据见 PLAN.md 海面修复记录。


## 原生海洋运动

用户反馈轮廓修复后横移仍抖动，并授权必要的算法修改。根因：80列每次移1列再按
floor(x*79/59)取60列，源索引间距为1或2，不能表示显示域中严格的一列平移。
之前行归并只修了竖向缺口，没有移除横向空间混叠。

现在原生路径使用 ocean60.c，参考路径仍用原 ocean.c：

- 海洋状态直接为60×8 uint8_t；每次更新严格左移1格，生成最右新列，直接写入char_buf。
- 连续波形直接量化到0–7行，不再生成10行后抽样/合并。波形相位逐新列加1，各海洋独立。
- 故障在新列生成时决定并存入状态，之后随水流移动；取消整片海洋每帧重新随机替换。
- 海洋以开始时从主RNG抽取的1个种子初始化独立xorshift32；更新不再消耗主RNG。
  故障强度改变会随新列逐步传入，最多60次更新替换整片水面；颜色事件仍立即作用全海面。
- 海洋更新节拍沿用原调度。每次显示域平移1格，比旧不均匀采样的平均约0.75格更快，
  波长和随机细节也与旧版不同。这里保证匀步移动，不声称实现了子字符像素插值。
- 由于取消旧海洋的大量主RNG消耗，后续天气、随机进度等也会出现不同但可重放的随机细节。
  文字初始化仍在播放前完成。原始Python/终端参考未改。

验证以原生算法性质为准：4800次更新、2265600个格验证 old[y,x+1]==new[y,x]，
297次实际framebuffer对照验证同一水面恰好左移4个VFD像素；无故障时每列恰有一个#，
上空/水下字符正确。覆盖seed0/1/42及5档故障强度，双实例可重放，独立相位，更新不消耗主RNG、
不分配内存。新增测试 ocean60_motion 替换旧的重采样oracle。

三种子×六跳转的72132帧现在对照确定性的调度、事件、文字偏移及历史；明确不比较已授权改变
的海洋/RNG/天气/随机进度。标题4584帧像素保持一致，完整视觉效果待用户复看。

最新profile：x64 Ocean=504 B（原3216），Credits=10776 B；ARM Ocean=496 B、Credits=10264 B。
堆峰值仍为主机25184 B、ARM投影20116 B；fb4096 B；ARM主要对象总计34476 B / 33.67 KiB，
比上版再减少8136 B。仍为39次分配、释放live=0，无海洋/画布帧分配，不计目标栈/分配器/驱动。
主机 ocean_update 单函数静态栈72 B、column120 B，不是目标调用链预算。
